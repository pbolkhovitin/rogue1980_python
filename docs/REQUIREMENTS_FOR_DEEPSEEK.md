## 2. Rules (Правила разработки)

### Архитектурные правила
- Строгое разделение слоев: `domain` НЕ импортирует `presentation` и `data`
- Использование dependency injection для связи слоев
- Состояние хранить в объектах (GameSession, Level, Player), избегать глобальных переменных

### Стандарты кода
- **Модульность**: максимум 300 строк на файл, одна сущность — один файл
- **Типизация**: все аргументы аннотированы, `from __future__ import annotations`
- **Именование**: `snake_case` для функций/переменных, `PascalCase` для классов, `UPPER_SNAKE_CASE` для констант
- **Документация**: docstring у каждого публичного метода (назначение, параметры, возврат)
- **Обработка ошибок**: не использовать голые `except:`, ловить конкретные исключения

### Структура проекта
```
src/
├── domain/          # бизнес-логика, сущности, генерация, бой, ходы
│   ├── entities/    # Character, Player, Enemy, Item, Tile
│   ├── generation/  # генерация уровней, комнат, коридоров
│   ├── combat.py    # расчет hit/damage, apply_attack
│   ├── ai.py        # паттерны движения врагов
│   └── fov.py       # ray casting, Брезенхэм
├── presentation/    # curses-рендеринг, ввод, туман войны, интерфейс
│   ├── renderer.py  # абстрактный Renderer, Renderer2D
│   ├── input.py     # обработка WASD, h/j/k/e, цифры
│   └── ui.py        # статус-бар, инвентарь, меню, статистика
├── data/           # JSON-сохранение прогресса и статистики
│   └── game_data_manager.py
├── utils/          # константы, Tile, Position, Direction
├── config.py       # флаги BONUS_*
└── main.py         # точка входа, curses.wrapper
```

### Игровые механики (MVP)
- **Персонаж**: hp, max_hp, dex, str, weapon (может быть None), рюкзак (food/potions/scrolls/weapons ≤9, treasure — число)
- **21 уровень**: 9 комнат + коридоры, стартовая (без врагов) и конечная (лестница)
- **5 видов врагов**: Зомби, Вампир, Привидение, Огр, Змей-маг с уникальными механиками
- **Бой**: проверка попадания (dex), расчет урона (str + бонус), смерть, сокровища
- **Сложность**: растет с уровнем (врагов больше, сильнее, полезных предметов меньше)
- **Пошаговость**: ход игрока → все враги действуют
- **Туман войны**: ray casting + Брезенхэм, неизведанное скрыто, текущая комната видна полностью
- **Сохранение**: JSON после каждого уровня, статистика всех попыток (таблица рекордов)
- **Управление**: WASD (движение), h/j/k/e (использование предметов), 1-9 (выбор)

### Правила коммитов
- Работа в ветке `develop`, не пушить в `master`
- Коммиты атомарные: один логический блок изменений
- Формат сообщения: `[этап N] краткое описание`
- Запуск `pytest` и `mypy` перед коммитом (pre-commit)

## 4. Расширяемость для бонусов (MVP готовит архитектуру)

Бонусы 6-9 исключены из MVP, но архитектура готова к их добавлению:

| Бонус | Требуемая расширяемость | Реализация в MVP |
|-------|------------------------|------------------|
| Двери и ключи (6) | Проходимые/запертые клетки | `Tile` с атрибутами `is_door`, `locked`, `key_id` |
| Динамическая балансировка (7) | Адаптация сложности на лету | `BalanceAdjuster` (заглушка) |
| Мимик (8) | Новый тип врага-предмета | `EnemyFactory` с поддержкой Mimic |
| 3D-режим (9) | Альтернативный рендеринг | Паттерн Strategy для `Renderer` |

Флаги в `config.py`:
```python
BONUS_DOORS_AND_KEYS = False
BONUS_DYNAMIC_BALANCE = False
BONUS_MIMIC = False
BONUS_3D_RENDER = False
```

## 5. Критерии приемки для агента opencode

1. Код проходит `mypy --strict` (кроме curses-оберток)
2. Код проходит `pytest` без ошибок
3. Игра запускается и позволяет пройти минимум 3 уровня без краша
4. Сохранение и загрузка работают (после перезапуска игра продолжается с того же места)
5. Статистика записывается и отображается в таблице рекордов
6. При всех `BONUS_* = False` код работает без бонусных модулей

## 7. Процесс работы агента opencode

1. Получить задачу из `docs/TODO.md`
2. Написать минимальный код, реализующий задачу
3. Написать тесты (граничные случаи, покрытие)
4. Запустить тесты и `mypy`, убедиться в прохождении
5. Зафиксировать коммит с правильным форматом
6. Перейти к следующей задаче

**Важно**: Агент не должен добавлять функционал, не указанный в задании, и использовать внешние библиотеки, кроме стандартных.
